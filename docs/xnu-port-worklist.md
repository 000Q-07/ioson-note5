# XNU patch worklist for the Note 5

How the S8 port is layered (read from `Floppikrob/ios-galaxy-s8`):

1. `xnu/patches/0001..0123`: the shared SWEET + Galaxy A5 2016 series (machine
   config `A5XELTE`, 4 KiB pages, GICv2, S-Boot handoff).
2. `0124-dreamlte-s8.patch` (generated by `tools/dreamlte/apply-dreamlte.py`):
   everything that is specific to the S8's hardware.

The Note 5 equivalent is a **third layer**: `xnu/noble/apply-noble.py` runs on
a tree that already has 0001..0124 and swaps the S8 board-fact block for a
Note 5 one. The S8 patch and this layer are meant to be applied in that order.

## What exists in this repo

- `xnu/noble/apply-noble.py`: replaces the board-fact macro block in
  `A5XELTE.h` (framebuffer, entry marker, boot MPIDR, log region, timer
  choice). It was tested against the real header rebuilt from patches
  0085/0095/0112/0115/0124, and refuses to run on unknown values, on a double
  apply, or on a tree without 0124.
- `xnu/noble/board.json`: the facts it needs. **All are null.** They come from
  `tools/collect-facts.sh` and the `shim/noble` probe.

Not tested here: applying it inside a full XNU build. That needs the macOS CI
the S8 project uses (its `xnu` GitHub Actions workflow); no such build has been
run for the Note 5.

## What is NOT done: the per-file worklist

With `NOBLELTE` defined, every `#if defined(DREAMLTE)` site in the tree is off,
so those files fall back to the **Galaxy A5 (Exynos 7580)** code, which is
wrong for the 7420. Sites found in the S8's 0124 patch:

| File | What the S8 version does | Note 5 status |
| --- | --- | --- |
| `pexpert/.../A5XELTE.h` | board macros | done, needs measured facts |
| `osfmk/arm64/start.s`, `sweet_early.c`, `iokit/.../SweetFramebuffer.cpp`, `pexpert/arm/pe_serial.c` | early framebuffer console and display bridge, all driven by the `A5_FB_*` macros | should follow from the macros **if** the panel is a plain linear framebuffer; may also need the display-trigger unmask (unknown) |
| `osfmk/arm64/arm_vm_init.c` | the S8 pinned the physical-aperture slide to 0 and the pre-built L3 budget had to include the 17 MiB framebuffer. The Note 5 framebuffer is about 14 MiB: the same budget problem is likely | needs the same two fixes, adjusted; unverified |
| `osfmk/vm/vm_resident.c` | extra console marks around `vm_page_bootstrap` | optional debug aid |
| `iokit/Kernel/arm/SweetCPU.cpp` + loader `smp_probe.c` | boot MPIDR, and secondary cores only start after a PMU power-up that Samsung's own kernel does (Exynos PMU register writes) | **unknown for the 7420** (PMU registers, core numbering of its A57 and A53 clusters). Start with `cpus=1` |
| `osfmk/arm64/machine_routines.c`, `pexpert/arm/pe_fiq.c` | physical timer instead of the virtual one | depends on a measured fact (`use_phys_timer`) |
| `bsd/dev/sweet_ufs.c` + loader `ufs_probe.c` | UFS driver with S8-specific quirks, found by probing the host controller | **needs its own probing**: the Note 5 has UFS 2.0 on an older Exynos host generation. Without it there is no root filesystem |
| `bsd/dev/a5xelte_touch.c`, `a5xelte_keys.c` | S8 touch controller and button GPIOs | **unknown**: touch controller and GPIOs on the Note 5 not measured. Disabled by the generator (`A5_*_DEFAULT 0`) |
| `iokit/Kernel/arm/SweetBattery.cpp` | reads the S8's fuel gauge | unknown for the Note 5; a stub is enough at first |
| `iokit/Kernel/IOPlatformExpert.cpp` + loader `pmic.c` | clock from the S8's PMIC RTC passed as a boot arg | unknown PMIC/RTC on the Note 5; skip (clock shows 1970) |
| `iokit/KernelConfigTables.cpp` | platform / CPU personality names | add `noblelte` names |
| `tools/mkadt_dreamlte.py` | builds the Apple Device Tree XNU boots with | needs a `mkadt_noble.py`: RAM map and platform names from facts |

## Suggested order

1. Facts and the stage-1 probe on the phone (see README).
2. Fill `board.json`, run `apply-noble.py`, build XNU in CI, and aim for what
   the S8 reached first: CPU0 up, platform expert matched, stuck waiting for
   the root device ("boot 9" in `DREAMLTE_PROGRESS.md`).
3. UFS probe and driver, then the iOS root image.
4. Display bridge and touch.
5. Secondary cores, last.

## Boot arguments for the first attempts (from the S8 install guide)

`a5touchprobe=0` and low CPU count (`cpus=1`) were what kept the S8 stable
early on. Treat them as a starting point, not as verified for the Note 5.
